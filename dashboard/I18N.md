# Dashboard internationalization

The dashboard ships English, Spanish, Portuguese (Brazilian wording), French, Italian, German, Simplified Chinese, Arabic, Russian, Malay, Hindi, and Japanese. `pt` selects `pt-BR` formatting; `zh` selects Simplified Chinese (`zh-Hans`). The twelve catalogs have identical keys and interpolation parameters. English is the source and fallback. Product and protocol identifiers such as Docmon, Docker, MCP, JSON, REST, HTTP verbs, endpoint paths, image references, field identifiers, and raw JSON remain unchanged.

`src/i18n/localeRegistry.js` owns language metadata and aliases. Language resolution uses the persisted explicit choice, then the browser language, then English. The login and topbar selectors show native language names. Locale changes update HTML `lang`, `dir`, and the page title, and persist under `docmon.locale` independently of authentication. The initial locale loads before rendering the application. Other catalogs load on demand through i18next's backend adapter. `en-XA` expands text, and `ar-XB` combines expansion and RTL for layout testing.

Use semantic camelCase keys, `t("key")`, and `{{parameter}}` interpolation. Avoid translating fragments and concatenating sentences. Shared formatters accept the active locale for numbers, dates, times, byte sizes, percentages, durations, relative times, and lists. Binary byte unit symbols remain IEC identifiers. API requests include `Accept-Language`.

## Dynamic content

Docker resource identifiers, Docker status descriptions, logs, commands, and inspected JSON are diagnostic machine output and are displayed verbatim. Known state and update-status badges are translated. API operation labels use translated actions; the OpenAPI JSON schema itself remains the authoritative English technical contract. Backend errors provide stable codes. The UI shows a translated failure or authentication message, with the original diagnostic message and correlation ID available under Details. Server-authored diagnostic messages are not translated on the server; this preserves their exact content for troubleshooting.

## Adding or changing translations

Update `src/i18n/locales/en.json`, then all eleven translated catalogs. Preserve interpolation names and wire identifiers. Add a locale to the registry and create its JSON file; the loader discovers catalogs automatically. Product maintainers own source strings and glossary decisions; changes to wording must update catalogs in the same change. Native-speaker review is recommended for terminology and regional wording before release.

Glossary: a container is a Docker execution instance; an image is its packaged filesystem/configuration; a Compose project groups services; pull fetches an image; prune removes eligible unused resources; a bearer token authenticates machine operations. Do not translate registry names, image tags, paths, or executable arguments.

Run `npm run lint`, `npm test`, and `npm run test:e2e`. Lint checks literal UI/accessibility text and static translation keys. Unit tests enforce complete catalog keys and interpolation parity. Browser tests exercise all twelve languages and both pseudo-locales, persistence, RTL, navigation, and translated chrome. These checks run in GitHub Actions on every push and pull request.
